## Accounting and quality gates

Rates below are **native generated tokens divided by summed native decode time across all reasoning and answer phases**, excluding prefill, startup and injected API reasoning-wrap tokens. The API wrapper combines total output counts with the final native phase clock, so dividing those directly would overstate throughput. The compact JSON retains API output/reasoning counts and native phase totals separately. Answer/wall latency can improve because output becomes shorter; tokens/sec alone is not task completion speed.

Each valid screening artifact passed completion, exact model/request counter, timestamps and native phase attribution, exact retrieval and resource-warning gates. Cold artifacts also passed startup allocation evidence; hot artifacts link to their same-config cold artifacts rather than inventing allocation measurements. Cold engine startup does not mean cold ZFS/OS cache. Warm engine does not mean a cached prompt. Partial-prefix reuse is recorded from the first native phase, not the wrapper's final-phase cache counter. Large cold timing variation and adaptive expert/cache history confound one-shot rankings. No concurrency or maximum-context performance is extrapolated from short prompts.

MTP and KV code outputs were manually inspected and the isolated merge functions tested against 400 sorted input pairs each (empty lists, negatives, duplicates, uneven lengths), with inputs unchanged. All eight worker code functions also passed the same 400-pair checks; their logic matches previously reviewed linear merge implementations. Prose was manually checked for age-appropriate three paragraphs and roots collecting water/nutrients versus leaves making food. MTP window 3 prose had a minor “roots gather food” imprecision. These checks support this bounded prompt set, not general model correctness or every request being answered. Uncensored provenance is not a guarantee of zero refusals.
